# Gather v0.1.14

This one is about small computers: the local AI model no longer eats more and more memory
while it reads, and long documents are no longer cut in the middle of a sentence. Everything
still runs on your machine.

## What changed

- **The local AI model no longer grows without limit while it reads.** If you use Ollama as
  the model that reads your files, Ollama kept a copy of every section it had answered in
  memory, in case the same one came back. Gather never asks the same thing twice, so that
  memory only grew. On a test machine with `llama3.2:1b`, the model's memory climbed from
  1.9 GB past 2.8 GB and was still rising, enough to freeze a small computer. Gather now
  unloads the model after every 10 sections it reads and loads it again on the next one,
  in the background, which takes a few seconds. The model's memory comes back down to where
  it started each time. `GATHER_OLLAMA_REFRESH_AFTER` changes the number; `0` turns it off.
  Search by meaning is not affected: its model is small and does not grow.

- **Honest advice for small computers.** A model that reads files needs about 2 GB while it
  works (`llama3.2:1b` about 1.9 GB, `llama3.2:3b` about 2.6 GB). That is most of what a
  4 GB computer has to spare, so Settings now recommends search only there, the model field
  starts empty on a computer with little memory, and the install guide no longer suggests the
  1B model for 4 GB. Computers with 8 GB or more are unchanged.

- **Optional: stop the growth at its source.** If you start Ollama yourself, setting
  `LLAMA_ARG_CACHE_RAM=0` in *Ollama's* environment stops it keeping those copies at all. It is
  not needed — Gather copes without it — and how to set it on each system is in
  [CONFIGURATION.md](../CONFIGURATION.md).

- **Long documents are cut at the end of a sentence.** Text pulled out of a PDF often arrives
  as one long paragraph, and Gather used to cut it every 2,000 bytes wherever that fell. A cut
  through a sentence could lose a fact that straddled it, or keep each half as a statement of
  its own. Gather now cuts at the last sentence end, else the last line break, else the last
  space. On 300 test documents it recovered every statement a whole-document read finds, where
  the old cut lost 68 and invented 49 broken ones (the documents are synthetic, so this shows
  the mechanism rather than how often real documents hit it).

- **Security: seven advisories closed.** `zip` (three advisories, all about unpacking archives
  to disk, which Gather does not do: it reads archive entries in memory), `rustls-webpki`,
  `webpki-roots`, `webpki-root-certs` and `ctutils` were updated, along with `calamine`,
  `protox`, `tokio` and six desktop packages.

## Not changed

The better cutting applies to files read **after** you update. Documents already in your
library keep the sections they have; nothing is re-read automatically, and nothing is removed.
The periodic unload only happens if you have turned on a model that reads files; search-only
setups are untouched.
